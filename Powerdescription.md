# 2) Core Detection Principle (what the app must read)

* Because there’s no MCU link, the app must infer **start/stop** from the **phone’s charge/discharge current** (Android BatteryManager  **`BATTERY_PROPERTY_CURRENT_NOW`** ). App_Spezifikation_FERVIX-8-9-20…
* **Signal shape** : when the device is  **active (pressed)** , the phone’s  **negative charge rate is reduced by ~400 mA** ; when it  **stops** , it  **rises back by ~400 mA** . App_Spezifikation_FERVIX-8-9-20…
* **Key risks** to handle in code:
  * **Idle current is noisy** (background processes) → risk of  **false starts/aborts** . App_Spezifikation_FERVIX-8-9-20…
  * **OEM differences** in how current is exposed → need **fallback readers** and per-device handling. App_Spezifikation_FERVIX-8-9-20…

# 3) Plug-in Flow (what to do when connected)

1. On  **USB attach** , optionally **auto-launch the app** (toggleable in Settings). Open  **Home** . App_Spezifikation_FERVIX-8-9-20…
2. **Arm the detector** only for this device context (USB-C OTG present).
3. Run a **short calibration** period to learn the **idle baseline** before allowing a “press” to be recognized (see §4).

# 4) Robust Current-Delta Detection (practical recipe)

**Sampling & buffering**

* Foreground service while armed; sample current at  **~10–20 Hz** , make decisions at **~1 Hz** (rolling windows).

**Session calibration (after plug-in)**

* **Idle window** (e.g., first 8–10 s): compute baseline **μ₀** and noise **σ₀** from `current_now` while  **not pressed** .

**Press detection with hysteresis**

* Start when a **sustained delta** `ΔI = I − μ₀` stays above **`I_on`** for **T_on_sustain** (≈1.5–2.5 s).
* Stop when `ΔI` falls below **`I_off`** for **T_off_sustain** (≈1.0–1.5 s).
* Choose thresholds relative to both **expected draw (~400 mA)** and observed noise, e.g.

  * `I_on = max(0.55·400 mA, k1·σ₀ + m1)`
  * `I_off = max(0.25·400 mA, k2·σ₀ + m2)`
* Filter spikes with a **median/MAD or Hampel** filter, then a light **EMA** to stabilize the stream.

  *(The ~400 mA figure and the “active reduces negative rate by ~400 mA” come from the spec; the exact filter/threshold choices are the recommended engineering approach.)* App_Spezifikation_FERVIX-8-9-20…

**State machine**

* `Idle → PreHeat → Treatment → Done`, with **Abort** if stop is detected early. (This aligns to the functional flow in the spec.) App_Spezifikation_FERVIX-8-9-20…

**OEM fallbacks**

* Prefer `BatteryManager.getLongProperty(CURRENT_NOW)`. If unavailable/noisy, attempt **vendor power paths** (read-only `current_now` under `/sys/class/power_supply/*`) or other available battery telemetry; ship with **device-specific toggles** if needed (the spec flags OEM inconsistency). # 5) App Behavior Tied to Detection

* **No false timers** : The app **must not** start preheat if the device isn’t truly active; **must stop** if activity ceases. The spec enumerates the failure modes we must avoid. App_Spezifikation_FERVIX-8-9-20…
* **Pre-heat & Treatment durations** are computed from the **heating/cooling functions** using the **ambient T₀** (ask user; cache last; **default 27 °C** if unknown/offline). App_Spezifikation_FERVIX-8-9-20…
